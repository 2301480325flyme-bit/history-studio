# History Video：从一句话到成片

Studio（`01_工作流/history-studio/`）是棋盘：内置地图、地名库、动画和渲染。你是棋手：负责研究、编剧、落子（写 `episode.yaml`），并对结果负责。
脚本格式以 `01_工作流/history-studio/SCRIPT.md` 为准。开工前先读它；样例见 `01_工作流/projects/studio-*/episode.yaml`。

所有命令都在 `01_工作流/history-studio` 下运行，先设置 `$env:PYTHONIOENCODING='utf-8'`。

## 0. 明确题目

从用户的话里取出四样东西：
- 题材；
- 时间范围；
- 时长：未指定时默认 60–90 秒，约 10–16 拍；
- 视角：未指定时按时间顺序讲因果。

题目若来自演义（"十八路诸侯""三英战吕布""草船借箭"等），照做，但要按正史讲，并在 `notes` 和旁白中点明演义与史实的差别。不要拒绝，也不要回问；只有题材本身有歧义时才问。

## 1. 研究（产出：事件表）

**2026-10-24 起，研究交给 Codex 做「史料包」**（格式和派活方法见 `01_工作流/history-studio/协作-Codex.md` 第二、三节），最好提前 1–2 集派出。Claude 读史料包写大纲，并抽查至少 3 条原文。下面的方法是 Codex 做史料包时用的，也是 Claude 抽查时用的。

1. 本地正史优先：
   ```powershell
   python studio.py sources 关键词1 关键词2 --books 三国志 后汉书 --limit 15
   ```
   - 关键词可以组合人名、地名、动词（屯、讨、败、诛、迁）。
   - 结果里每条都有段落 ID，引用时用它。
   - `damaged: true` 或文中有 `□` 的是 OCR 缺字，要从别处补证，不要猜字。
2. 交叉核对：同一事件至少找两处，例如纪传互见，或用《资治通鉴》对照。
3. 网络资料用来补全卷次链接（维基文库）、现代研究对争议的结论，以及地点的今址。网页说法不能取代原文出处。
4. 整理成事件表：时间、人物、地点、发生了什么、原文摘句、出处。

## 2. 编剧：写旁白（最重要）

**先读并严格执行 `.claude/skills/history-narration/SKILL.md`**，它规定了钩子、结构、语速和口语化标准；下面是摘要。

旁白是写给耳朵听的现代汉语，**不直接念文言**。要求：
- **短句**：每拍一句话，12–28 个字（约 3–6 秒）。一拍只讲一件事。
- **口语**：把"卓闻兵起，乃徙天子都长安"改成"董卓听说关东起兵，干脆挟持皇帝，迁都长安。"
- **因果清楚**：用"于是""可是""结果""没想到"串起情节；每 3–4 拍要有一个推进或转折。
- **结构**：开场钩子（一句话抓人）→ 背景 → 经过（冲突升级）→ 结局 → 余韵（一句话点出它为什么重要）。
- **数字写汉字**：公元一百九十年、十余路。这样 TTS 读得准，ASR 也能比对。
- **人名**：首次出现说全名并带身份（"渤海太守袁绍"），之后可以用简称。遇到生僻字和多音字（如"伷""颙"），尽量换一种说法，或者避免放在句首。
- **原文点睛**：确有名句时，可以引半句原文并紧跟白话解释，全片最多一两处。
- **不演绎**：不写原文没有的心理、对白和数字。推测性的话加"据说""或许"，并在 `notes` 里说明。
- **字幕**：`caption` 是旁白的精简版，不超过 18 字。

每拍都写 `sources`（出处 ID）和 `quote`（对应的原文摘句，可截短）。审稿单会把它们并排列出。
- maindata `citations.json` 没有的出处，写进 `sources_local`：`{id, work, volume, url}`。卷次核对不了时，`volume` 写"卷次待核（语料段落 三国志-p00038）"。

## 3. 地点

新地点的考证（古今对照、谭图坐标、城邑等级）可以交给 Codex：一次派一批，任务单把 `gazetteer.json` 列进可写范围；不在同一时间派两个改它的任务。

1. 先列出全片地点，批量查询：
   ```powershell
   python studio.py places 酸枣 河内 颍川 --year 190 --web
   ```
2. 本地库有就直接用。没有的，**先查本地谭图** `02_数据/历史地图集/<朝代>/`（扫描图，按图上经纬网读出坐标，只用来定位，不把图放进视频）；谭图也找不到，才从 Wikidata 候选中挑选。只挑描述是"旧县名""古城""遗址"的条目，不要挑演义地名或现代同名地。
3. 用网络资料核对今址，然后入库：
   ```powershell
   python studio.py place-add --id suanzao_county --name 酸枣 --lon 114.20 --lat 35.15 `
     --precision "东汉酸枣县治近似点（今延津县西南）" --source https://www.wikidata.org/wiki/Q113652019 --years -200-600
   ```
   入库后，后面的集数直接复用。精度要写清楚：遗址点、县治近似，还是现代同名近似。
4. 实在定不了的地点，就不上图，旁白里用文字带过；或者选一个确定的邻近大城，并在 `detail` 里注明。
5. 河流（汴水等）不是点，不要建成地点。用 `card` 说明，或者干脆不画。

## 3.5 割据题材：写势力控制表

题目涉及多方势力（群雄割据、三国、十六国、南北朝、五代等）时，用 `territory` 加每拍的 `owners` 来表达局势，不要画手工疆界。
- 先确认这个时代有没有郡格子（`data/cells/`）。东汉三国用 `han-140`；其他时代要先按 `data/README.md` 的方法建一套。
- 局势按州写，例外按郡写（点名到郡的优先于整州）。每个局势都要有出处，并在 `quote` 里摘录原文，例如"兼四州之地"。
- 拿不准的郡放进 `uncertain`（画斜纹），并在 `notes` 里说明原因。不要为了画面完整而硬分配。
- 每个势力指定 `label_at` 为都城，色位使用 `palette.json` 里的名字。主角势力加 `main: true`，会用柔和色。
- 全景镜头建议以襄阳一带为中心、缩放约 0.62；讲到边地势力时，用 `shift` 把它们移出字幕条的遮挡区。

## 4. 落子：写 episode.yaml

**先读并严格执行 `.claude/skills/history-storyboard/SKILL.md`**（两秒规则、cue 对准台词、动词→画面配方、镜头编排）。配音参数按 `.claude/skills/history-voice/SKILL.md` 设置。

- `map`：
  - 一律使用 `basemap: dem`。它可以商用；旧的 `relief` 只能内部预览。
  - `center` 取全片地点的中心；
  - `scale`：中原一隅约 9000–12000，跨数州约 5000–7000，全国约 3500；
  - `extent` 要比镜头最远处再宽 3–5 度；
  - `focus_zoom` 是单城特写的缩放，默认 2.0。
- `factions`：阵营配色，如 `{联军: red, 董卓: black}`。旗牌用 `faction:` 指定阵营。
- 镜头：大多数拍不写 `camera`，会自动跟随本拍涉及的地点。开场全景、收尾回拉和需要特写的地方才手写。
- 画面语法（动词对元素）：

| 旁白里有 | 放什么 |
|---|---|
| 某人 起兵 / 屯驻 / 镇守 某地 | `flag`（阵营色），城点 `highlight` |
| 从 A 进军 / 迁往 B | `arrow`：原文写明了起止才用 `recorded` 并附 `evidence`，否则用 `direction` |
| 结盟、遥相呼应、上下级关系 | `arrow kind: relation` |
| 战于某地、大败、击破 | `battle`（`title` 写结果，`text` 写谁对谁） |
| 被杀、篡位、投降、焚城 | `stamp`（诛 / 篡 / 降 / 焚） |
| 关键人物第一次登场 | `portrait`：有 maindata 肖像就用 `person`，否则只写 `name` + `title`，画成文字人物卡，不编造人脸 |
| 章节转折、事件定性 | `headline`，全片 1–3 次 |
| 需要解释的背景或史实说明 | `card` |

- 同屏元素不超过 4 个，旗牌出场后要用 `until` 控制退场，别让画面越积越满。
- `notes:` 写史实说明，比如演义与正史的差别、争议、做了取舍的地方。

## 5. 自检循环（必须跑完）

```powershell
python studio.py check ..\projects\<id>\episode.yaml --json   # 有 error 就自己改，直到 ok
python studio.py build ..\projects\<id>\episode.yaml --voice placeholder --build P1   # 先无声排版
python studio.py still ..\projects\<id>\episode.yaml -t <每拍中点…>
```

**亲自看每一张抽帧**（用 Read 打开 png），检查：
- 标签、旗牌、卡片有没有互相遮挡；
- 焦点是否清楚，城点是否在画内；
- 箭头方向对不对；
- 字幕是否压到别的东西。

有问题就改 YAML 重建，排版没问题后再配音：

```powershell
python studio.py build ..\projects\<id>\episode.yaml --build S1   # voice.mode: mimo，含 ASR 听写校对
python studio.py render ..\projects\<id>\episode.yaml
```

- ASR 报告中一致度低于 0.92 的句子，先判断是 TTS 读错，还是 ASR 听错。
- 读错的，改写措辞避开那个字，再重建；改过的句子才会重新合成。
- 最后看 `contact-sheet.jpg` 和 `media-check.json`，确认 `full_decode_ok`。

## 6. 交付

告诉用户：
- 成片路径；
- `review.md`（审稿单：旁白与原文对照、地点精度、箭头性质、ASR 结果、警告）；
- 你做过的史实取舍，以及本集新入库的地点（这些地点待人工复核）。

不要说"已验收"。史实、读音和画面的最终判断属于用户。

## 红线

- 不编造疆界，不把示意路线画成史载路线，不编造人物肖像或原文。
- 不把演义情节当史实讲。要讲的话，必须明说"小说里……，史书上……"。
- MiMo 配音会把旁白文本和参考音发送到服务端；参考音只用已授权的样本。
- 构建目录不覆盖；`05_项目/Remotion/studio/<id>/` 下面每次都是新的构建编号。
