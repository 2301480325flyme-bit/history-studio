# 配音表演规范（MiMo TTS）

目标：语速接近示例视频（约 5 字/秒），句内紧凑，转折处有起伏，收尾有落点。**最终好不好听，必须由用户试听判断**；机器只能检查语速和读音。

## 一、实测依据（2026-10-07，同一句台词、同一参考音）

| 版本 | style 提示 | 实测语速 | ASR |
|---|---|---|---|
| A 原样 | 无 | 3.1 字/秒 | 一致 |
| B 紧凑 | 语速偏快，节奏紧凑，像短视频里讲历史故事，句子之间不拖沓。 | **5.9 字/秒** | 一致 |
| C 起伏 | 讲故事的语气，前半句平稳交代，转折后语气上扬加快，最后一句带惊讶和反问感。整体语速偏快。 | 3.9 字/秒 | 一致 |

三段样音在 `06_报告/配音语气对比-20261007/`。**2026-10-07 用户试听后选定 C（讲故事的起伏）为默认风格。**
C 的语速约 3.9 字/秒，低于目标，因此默认加上 `speed: 1.15`，用保持音调的变速把语速补到约 4.5 字/秒。用户觉得太快时，先去掉 speed。

## 二、标准配置

```yaml
voice:
  mode: mimo
  provider: clone                       # 已授权的参考音复刻
  reference: 03_素材/配音参考/studio-voice/studio-voice-v2.wav   # 自有 AI 音色（V2，用户选定；不用周涛）
  style: 讲故事的语气，交代处平稳，转折处语气上扬、加快，结果处下沉留白，整体语速偏快。
  speed: 1.2                            # V2 复刻 + C 语气实测 3.7 字/秒，×1.2 ≈ 4.4
  rate: 4.8                             # 2026-10-08 起：每句按实测语速单独变速到 4.8 字/秒（0.9–1.45 倍），解决忽快忽慢；≤8 字的收束句保留部分慢
  gap: 0.15                             # 句间停顿：短视频要紧
  bed: original
  bed_db: -21
```

## 三、单拍表演（`style` / `pause` / `speed`）

用三类语气就够了，不要每拍都写：

| 拍的类型 | `style` | `pause`（本拍前） |
|---|---|---|
| 钩子、转折、反问 | 语气上扬，节奏加快，带一点悬念感，像在问观众。 | 0.3–0.5 |
| 交代、推进（默认） | 不写，沿用全局 style | 默认 gap |
| 结果、收束、死亡 | 语速放慢，语气下沉，句末留一点余音。 | 0.6–0.9 |

- **不要逐字指定重音**。以前试过，H 方向的反馈是重音落错了位置。起伏要靠句子结构和标点来做。
- 标点就是节奏：
  - 逗号是短停，句号是中停；
  - "——"制造顿挫（"结果——一仗都不敢打"）；
  - "？""！"带出语调；
  - 别连用省略号。
- `speed`（保持音调的变速）只在 style 提示不够时使用，范围 1.05–1.2。超过 1.25 会发尖。

## 四、校对与验收

1. 构建时会自动用 MiMo ASR 逐句听写，结果写入 `voice/asr-report.md`。一致度低于 0.92 的句子先判断是谁的错：
   - **TTS 读错**：改写台词。加身份做上下文，或换一个说法。
   - **ASR 听错**：在审稿单里注明，留给人工试听。
2. 校验器会提示实测语速低于 4.0 字/秒的拍。目标是 4.5–5.5 字/秒。
3. 混音：声音床 -20 到 -24 dB，人声出现时自动压低。
   - 2026-10-28 起，混完整集统一调到 -16 LUFS：整体加一个固定增益，再用快速限幅器把峰值压在 -1.5 dB，人声本身不压缩。
   - 原先只做峰值缩放，第 43 集只有 -20.5 LUFS，各集之间也差几个 dB。
   - 某集要另设目标，在 `voice:` 里写 `loudness:` 或 `true_peak:`。
   - 每次构建的 `build.json` → `audio.loudness` 记录调整前后的响度。
4. **必须交给用户试听**：人名读音、重音、整体节奏和情绪。不要宣称"配音已验收"。

## 五、读音高风险字（写稿时就要避开或加上下文）

伷 颙 乂 燮 瓒 邳 郯 鄄 郏 莒 犍为（qián） 番禺（pān） 龟兹（qiū cí） 单于（chán） 可汗（kè hán） 吐谷浑（tǔ yù hún） 冒顿（mò dú） 阏氏（yān zhī） 万俟（mò qí）

已实测读错的词（V2 音色）：**"讨董"** 常被读成"陶董"，两次配音都错，改说"讨伐董卓"或"十几万人的联盟"。

在旁白里第一次出现时，带上身份或地名作为上下文，然后看 ASR 结果。仍然读错，就换说法，例如"鲜卑首领"代替生僻人名。

## 六、合规

- MiMo 调用会把旁白文本和参考音频发送到服务端，并按量计费。
- 不得使用周涛等真人声音（用户没有授权）。默认参考音为自有 AI 音色 `studio-voice-v2.wav`，见同目录 README。

## 七、MiMo 高级用法（2026-10-08 实验，见 `06_报告/配音实验-20261008/试听.html`）

- 导演模式：user 消息写「角色 / 场景 / 指导」三段，语速明显更快更有劲（实测 5.9 字/秒），但句间仍有波动。
- 音频标签：assistant 文本开头 `(沉稳 干练)`，句中可插 `[停顿]` `[语气一紧]` 等；句间最稳（波动 0.35）。
- 预置男声「苏打」「白桦」：不用复刻，但偶尔会多说一串乱码，必须靠 ASR 重试兜底。
- 无论用哪种，出片流程都会按 `rate` 逐句校准语速；选方案主要听音色和语气。
- 断句（第二轮）：模型在同一句里会抢快某个分句（实测 5.8 / 9.0 / 8.1 字/秒），逗号停顿 0.09–0.27 秒不等，片段首尾还各带 0.2–0.5 秒空白。`rate` 模式现在按逗号把每句切成分句，逐个分句变速（0.65–1.5 倍），逗号停 0.2 秒、句号 0.3 秒，句首 0.06、句尾 0.1 秒。切出的段数和标点对不上时退回整句变速。
- 导演模式不要写"语速偏快"——会让模型抢快中间分句；改写"每个分句同样的中等偏快语速，情绪靠语调和重音，不靠改变语速"（实验方案 B2，`tools/voice_lab.py`）。
- 节奏以音色的自然讲述为准（2026-10-08）：用户认可的节奏 ≈ 定妆样音，整体（含停顿）约 3.2 字/秒；分句语速约 4.0 字/秒，`pause_scale` 约 2.2（逗号 0.44、句号 0.66、句间 0.7 秒）。不要为了时长提速。

## 八、当前默认（2026-10-10 用户选定白桦，取代 D6 克隆）

```yaml
voice:
  mode: mimo
  provider: preset           # MiMo 内置音色（不克隆）
  voice: 白桦                 # 男声，偏低；内置中文音色只有 mimo_default、冰糖、茉莉、苏打、白桦
  unit: chapter              # 每章（phase）整段合成
  tag: "(讲述 平稳 连贯)"
  pause_cap: 0.3
  tempo_target: 4.3          # 整集一个调速倍数（tempo_scope 默认 episode）
  gap: 0.5
  bed: original
  bed_db: -26
```

- 为什么不用 D6：克隆音色每章分开合成时会变声（第 1 集从"苍天已死"起像换了人）；内置音色每次调用都是同一个人，两章之间的差别约为 D6 的一半。
- 不要整集一次合成：MiMo 读七百多字会读串、漏掉后半段。
- 合成后自动做：整集统一调速；各章音色（±5 dB 以内）和响度拉齐；旁白定在 −24 dBFS 左右，软限幅；ASR 逐章核对，并检查"就在就在"这种台词里没有的重复，有就自动重录。
- 克隆音色（`provider: clone`）仍可用：第 2 章起自动以第 1 章成品为参考（anchor）。Gemini（`provider: gemini`，密钥变量 `GEMINI_API`）免费档每天只有 10 次。
- 原则不变：语言到，画面到。配音定稿后不再为画面改动声音；画面按每句的时间点落。

## 九、系列读音表（2026-10-11）

多音字、生僻姓名读错时，不改台词，在 `01_工作流/series/三国到隋/读音.yaml` 的 `spoken:` 里加一条"原文: 同音同字数替换"（如 `麴义: 曲义`、`长子: 掌子`、`长史: 掌史`）。
引擎只替换送进配音引擎的文字（旁白和人物台词都生效），字幕仍显示原字；改表后重新构建，只有含这些词的章节会重新合成。
写新集时先查表里有没有要用的词；用户指出的读音错误一律进表，全系列生效。

**读音预检（2026-10-28 起）**：`studio.py check` 和 `build` 会自动列出没核过读音的词——人名、地名里容易读错的多音字（乐、单、会、番、朝、燕、阆、沓……）和生僻字，一批古称（禅让、单于、仆射、降将、燕王……），以及 GB2312 以外的字。每个词核一次：读得对的写进 `读音.yaml` 的 `confirmed:`，读不对的在 `spoken:` 里写同音替换，以后全系列不再提示。pypinyin 的猜测只作参考，它常把史书读音读成现代读音（刘禅 chán、朝歌 cháo、阆中 láng），以史书读音为准；拿不准的写「未核」，不要猜。全系列扫一遍：`python history-studio/polyphone.py --all s01e18 s01e43`。
注意：读音识别（ASR）对不上原文时，可能只是同音字（善→禅、章→张）；而 ASR 对上了，也不代表读对了——它会按词义把读错的「禅让」照样写成「禅让」。所以读音要靠预检，不能只靠 ASR。

## 十、配音引擎会拒绝的说法（2026-10-11）

MiMo 对过于血腥或描述自杀细节的句子会直接不返回音频（构建报 `MiMo TTS response did not contain base64 audio`）。
实测被拒："他先勒死了自己的姐妹妻儿，然后点火自焚。" 改成"他带着全家，点起一把大火，死在了易京。"即通过。
处理办法：旁白换成克制的说法，原文放进 `quote` 引文卡（屏幕显示，不送配音）。识别服务（ASR）偶尔也会拒绝这类片段，引擎会标"读音未能自动核对"，审片单里人工听一下。
