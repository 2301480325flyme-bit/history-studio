## 二、⭐ 最有价值的成果：许昌坐标争议已解决

原判断（"采纳策展值"）**是错的**。查证后：

| 来源 | 坐标 | 与国保单位公布值差距 |
|---|---|---|
| `kings.json` | 114.00971, 33.99189 | **0.92 km** ✓ |
| `places_curated`（原采纳） | 113.85, 34.03 | **16.2 km** ✗ |

**权威依据**：汉魏许都故城，**第七批全国重点文物保护单位（编号 7-0328-1-328）**，
公布坐标 `33.98937194°N, 114.01926194°E`；许昌市建安区张潘镇古城村村坐标
`114.013258, 33.999383`。

**结论**：`places_curated` 那个点位于**现代许昌市区**，不是汉代城址；
`kings.json` 的值才对。已按证据改采纳，并在 `places.json` 写入完整 `coordinateEvidence`。

> 原 `places_curated` 的 `reviewNote` 自己就写着
> 「legacy pilot approximation」——早就承认是示意点。


## 七、核心命题的回答

> **「24 史批量出片」到底行不行？**

**技术上：行。** 链路已全程打通：
```
corpus/*.jsonl（33 万段原文）
  → extract_events.py（事件候选 + source_ids + 年份）
  → compile_story.py（模板 → episode JSON）
  → manifest.json（注册）
  → remotion render（成片）
```

**但"批量"的真正瓶颈不在技术，在数据：**
1. 每条候选事件都**必须人工审**（史料依据、旁白措辞）
2. 主表只覆盖 13 地点 / 8 人物，抽一集就冒出 64 个待补实体
3. 语料仍有 0.676% 损坏（南史 `F`=众 等）

**所以准确的说法是**：管线能批量**产出候选**，但成片仍是"人工审一条、出一集"。
这与「史图记忆簿」的实际产能（1 人 + 1 家属）是吻合的。
