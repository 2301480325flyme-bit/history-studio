# 可复用资产清单 v1 —— 你没想到的那些

> 2026-10-06 · 回应「还有什么可以复用的，是我没想到的」
> **核心判断：你现在的复用思考停在「画面元素」层，而那一层的杠杆最小。真正值钱的是「数据实体」和「叙事结构」。**
> 本文所有结论都有实测证据（见第二节）。

---

## 一、三层复用模型

| 层 | 复用对象 | 省什么 | 量级 | 你想到了吗 |
|---|---|---|---|---|
| **L1 画面元素** | 动画原语、城池符号 | 重复绘制 | 分钟级 | ✅ 想到了 |
| **L2 数据实体** | 地名、人物、政权、史料、纪年 | **重复查证与录入** | **小时级** | ❌ |
| **L3 叙事结构** | 事件序列、运镜句式、节奏、版式 | **重复构思与排版** | **天级** | ❌ |
| **L4 负资产** | 缺项清单、失败经验、审计记录 | 重复踩坑 | 天级 | ❌ |

**同样叫"复用"，L2 比 L1 值钱一个数量级，L3 值钱两个。**

## 二、实测证据（这不是猜测）

我扫了项目数据，发现四件事：

### 证据 1：地名主表严重不全，且**没被真正使用**

| | 数量 | 位置 |
|---|---|---|
| `places_curated.json` 地名主表 | **5 条** | `01_工作流/places_curated.json` |
| `dynasty/*/kings.json` 实际用到的城池 | **9 个** | 每个朝代目录各存一份 |

主表只有 `ye_city / luoyang_han_wei / changan_han_city / xuchang_approx / nanjing_ancient_city` 五条，**但八王之乱一集就用了 9 个城**——主表根本没被当权威源用。

### 证据 2：⚠️ **同一个洛阳，两个坐标，差 2 公里**

| 来源 | 洛阳坐标 | 长安坐标 |
|---|---|---|
| `places_curated.json` | `112.6183, 34.7195` | `108.8931, 34.2941` |
| `dynasty/八王之乱-起兵/kings.json` | `112.59631, 34.73157` | `108.93719, 34.31799` |
| **差值** | **≈ 2.1 km** | **≈ 4.0 km** |

**这是没有主表的直接代价**——同一座城，做地图时到底用哪个？而且这还只是同一集内的分叉；跨集只会更乱。

### 证据 3：人物与城池在**跨集重复录入**

`八王之乱-301/kings.json` 和 `八王之乱-起兵/kings.json` **录的是同一批 8 个人（司马伦、司马冏、司马颖、司马颙、司马越、司马乂…）、同一批 9 座城。** 人物字段里还带着 `color` / `lon` / `lat` / `realm` / `realm_valid` —— **等于每个人物、每座城，在每个用到它的集数里都要重录一遍。**

### 证据 4：画面版式**代码写了两遍**

- `HistoryShot.tsx`：标题区 + 年份徽标 + 精度声明 + 字幕条
- `Root.tsx` 的 `BWShot`：**同样四个区块又写了一遍**

改一次版式要改两个文件——这就是没抽 `Layout` 组件的代价。

## 三、L2 数据实体：六张主表（最大杠杆）

### 3.1 地名主表 `places`（⚠️ 已有但残缺，先修）

已有 `id / aliases / coordinates / coordinatePrecision / names[]`——**结构是对的**，问题是只有 5 条且没被使用。

**要做**：扩到覆盖全部用得上的地名 + **强制 dynasty 数据只引用 id，不写坐标**。

```json
{ "id": "luoyang_han_wei",
  "aliases": ["洛阳", "洛陽", "洛", "LuoYang"],
  "coordinates": [112.6183, 34.7195],
  "coordinatePrecision": "approximate",
  "names": [ { "text": "洛阳", "from": -202, "to": 907 } ],
  "tiers": [ { "from": 265, "to": 316, "tier": "capital" } ] }
```

> **`tiers` 字段是关键**：同一座城，在东汉是都城、在魏晋是都城、在唐是东都——**坐标不变、等级变**，正好接上符号库的 `upgraded` morph 状态。

### 3.2 人物主表 `persons`（❌ 完全没有）

一个人物跨多集出现（司马越出现在八王之乱的每一集）。现在每集重录。

**必须有的字段，尤其 `aliases`：**

```json
{ "id": "sima_yue",
  "names": { "formal": "司马越", "title": "东海王", "alias": ["东海王越", "越"] },
  "aliases": ["司马越", "东海王", "东海王越"],
  "life": { "birth": null, "death": 311 },
  "identity": "宗室·八王之一",
  "color": "#8d6e63",
  "portrait": "portraits/sima_yue_sq.png" }
```

> **别名归一才是真痛点**：文言文里同人异名极多。**王浚 / 王濬**（两个不同的人，同音）、**刘备 / 先主 / 玄德**（同一人三名）。没有 `aliases` 表，LLM 抽取时必然把一个人拆成三个人。**这是防幻觉的第二道闸门（第一道是地名）。**

### 3.3 政权主表 `powers`（❌ 完全没有）

政权的生命周期是**跨集的长期实体**：魏 220–266、蜀 221–263、东晋 317–420。

```json
{ "id": "eastern_jin",
  "name": "东晋", "aliases": ["晋", "江左"],
  "life": { "from": 317, "to": 420 },
  "color": { "fill": "#bc8f7d", "edge": "#8c3424" },
  "capital": "jiankang" }
```

现在这些颜色/国号散在每集数据里，改一次要改 N 处。

### 3.4 史料引文库 `sources`（⚠️ 字段已有，但每集重写）

`director.json` 已有 `sources[]` + 强制 `source_ids`——**机制是对的，但没有全局库**。

**要做**：建全局 `citations.json`，一条史料录一次，全项目按 `source_id` 引用。
```
{ "id": "jinshu-004", "citation": "《晋书·卷四·惠帝纪》",
  "edition": "中华书局点校本", "note": "永康元年正月条" }
```

### 3.5 纪年换算表 `chronology`（❌ 完全没有）

24 史用**年号 / 干支**纪年，视频要公元。**这是纯机械劳动，却每次都要人查。**

```
贞观三年   → 629
元朔三年   → 126 BC
永康元年   → 300
甲子       → 公元 4 年（依上下文朝代）
```

还要处理**帝王在位年**（"汉武帝元朔三年"）和**改元**（同一年多号）。
**做一次，全项目终身复用。** 这也是 P2 抽取器能自动化的前提。

### 3.6 别名归一表 `aliases`（并入 3.2 / 3.1，但值得单列）

地名有（`places.aliases` 已实现），**人物没有**。
- 地名：邺 / 鄴 / 邺城 / Ye / Yecheng ✅ 已有
- 人物：❌ 需要
- 政权：❌ 需要（"晋" 是西晋还是东晋？必须按年份判定）

## 四、L3 叙事结构：四类模板（杠杆最大，也最反直觉）

### 4.1 事件序列模板 `eventSequence`

历史事件有**固定模式**。给定谓词就能生成一串分镜：

| 模板 | 序列 |
|---|---|
| **起兵模板** | 起兵(`raise`) → 进军(`march`) → 交战(`defeat`) → 攻取(`capture`) → 善后 |
| **篡位模板** | 专权 → 废立(`depose`) → 篡位(`usurp`) → 清洗(`kill`) → 定都(`move_capital`) |
| **灭亡模板** | 围城(`siege`) → 陷落(`fall`) → 出降(`defect`) → 封号 |
| **北伐模板** | 誓师 → 行军 → 对峙 → 决战 → 退兵 |

**粒度比单个 verb 高一档。** verb 是"砖"，eventSequence 是"墙"。
**这正是白虹说「1. 2. 3. 4.」分点结构的本质**——它其实就是人肉版的 eventSequence。

### 4.2 运镜句式 `cameraPhrase`

不是单个 `dolly_in`，而是**镜头组合模式**：

| 句式 | 组成 | 用途 |
|---|---|---|
| **交代句式** | 全景 `hold` 1s → `dolly_in` 到焦点 → 到达后 `hold` 2s | 每段开头 |
| **战斗句式** | 全景 → 快推 → `shake` → `hold` 定格 | 交战瞬间 |
| **对比句式** | 左区域 → `pan` 到右区域 → `hold` | 双方态势 |
| **收尾句式** | `dolly_out` 拉全景 → `fade` | 段落结束 |

**比单个镜头值钱得多——因为它编码了"节奏"。**

### 4.3 节奏结构 `pacingProfile`（最反直觉的一个）

**"一条视频的时长骨架"本身可以模板化：**

| profile | 结构 | 适用 |
|---|---|---|
| `short-60` | 钩子 3s + 事件 ×3 (15s) + 收尾 12s | 抖音单条 |
| `mid-180` | 钩子 5s + 章节 ×4 (35s) + 钩子 + 收尾 | 3 分钟 |
| `long-600` | 章 ×8 + 每章小钩子 + 结尾升华 | 合集 |

对应调研报告里的爆款节奏（0–3s 钩子、每 10s 一个记忆点）。**做一次，每条视频的时间结构直接套。**

### 4.4 画面版式 `layout`（⚠️ 已双写，立刻该抽）

`HistoryShot.tsx` 和 `Root.tsx/BWShot` 里的四个版式区块**写了两遍**：
标题区 / 年份徽标 / 精度声明 / 字幕条。

**要做**：`<Layout slots={{ title, subtitle, yearBadge, disclaimer, narration }} />`，两个 shot 组件都复用它。

### 4.5 文案句式 `narrationTemplates`（顺手）

- `公元{X}年，{地点}。{事件}。`
- `至此，{政权}灭亡。`
- `{人物}以{身份}入{地点}。`

**做一次，LLM 抽取时直接套句式填空**，比自由生成稳定得多。

## 五、L4 负资产复用：复用「不做什么」

**这是最反直觉的一层——复用失败经验，比复用成功经验更省时间。**

| 资产 | 内容 | 已有？ |
|---|---|---|
| **缺项清单** | `unsupported[]`：本集哪些动作没实现 | 主链大纲提过，未落地 |
| **失败 checklist** | 投影 `/π` bug、海岸线造陆、AE Hue/Sat 不可加关键帧、抖音搜索页加关键词退化成 loading | ✅ 部分在 memory |
| **审计记录** | 源数据异常如实记录（不静默修正） | ✅ 已有原则 |
| **渲染指纹缓存** | 输入指纹 → 产物；改一个字幕不重渲整集 | 主链大纲提过，未落地 |

> **`unsupported[]` 尤其重要**：主链大纲里明确写了"无法实现的动作列为缺项"。**这个清单复用后，就不会每次都重新试错同一件事。**

## 六、优先级（按杠杆排序）

| 顺序 | 动作 | 理由 |
|---|---|---|
| **0** | **修坐标分叉**：统一 `places` 主表，dynasty 只引用 id | ⚠️ **这是数据正确性问题，不是优化**——现在同一座城两个坐标 |
| **1** | 抽 `Layout` 组件 | 消除双写，改动小、收益立刻可见 |
| **2** | 建 `persons` + `powers` 主表 | 消除跨集重复录入（已实测重复） |
| **3** | `places` 补齐 + 加 `tiers` 时间线 | 接符号库的 `upgraded` morph |
| **4** | `chronology` 纪年换算表 | 纯机械劳动，一次做完终身用 |
| **5** | 全局 `citations` 引文库 | 出处从"每集手写"变成引用 |
| **6** | `eventSequence` 事件序列模板 | 叙事复用，杠杆最大但需要前面就位 |
| **7** | `pacingProfile` + `cameraPhrase` | 节奏与运镜复用 |
| **8** | `unsupported[]` 缺项清单 | 负资产复用 |

---

## 七、一句话总结

> **你以为你在复用的是"动画"，其实最该复用的是"数据"和"结构"。**
> 动画复用省的是几分钟的绘制；主表复用省的是每一集重新查地名坐标、重新考证人物年代、重新写出处——那是小时级甚至天级的。
> **而且第 0 项不是优化，是 bug：你的洛阳有两个坐标。**
